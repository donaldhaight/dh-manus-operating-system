# VC/PE Capital Layer — Ethical Search-Demand and Editorial Map

**Purpose:** Build discoverability through clear answers to important operating questions. This is not a plan to deceive search engines, fabricate demand, misrepresent credentials, purchase authority, or induce investment activity.
**Reference date:** September 1, 2026.
**Editorial rule:** Every public page must state scope, source status, date, author/reviewer, commercial relationship (if any), and what cannot be concluded.

## 1. From “SEO bait” to evidence-backed demand capture

The durable alternative to bait is a **question-to-artifact system**. A page begins with a real question an operator, founder, advisor, or capital participant may ask. It provides a plain-language answer, a source-grounded explanation, a counterargument, a reusable template/checklist, a disclosure, and a next question. This produces useful material for traditional search, AI-mediated retrieval, direct sharing, and the Human Blockchain knowledge library.

| Do | Do not |
|---|---|
| Write the exact question in a natural-language title and answer it plainly. | Promise rankings, “secret” deal access, guaranteed returns, or insider information. |
| Attribute sources, date factual claims, and label judgment vs. evidence. | Invent data, case studies, reviews, credentials, outcomes, or testimonials. |
| Publish a reusable decision artifact. | Publish generic keyword pages with no original analytical value. |
| Explain sponsor, affiliate, provider, ownership, or referral relationships. | Sell editorial inclusion, favorable ranking, or access to a hidden audience. |
| Use human review on capital, legal, performance, and partnership claims. | Treat AI-generated output as publication-ready without review. |

## 2. Information architecture

The first site should use a small number of durable editorial hubs, not hundreds of keyword pages. Each hub has a glossary, source library, question index, version log, and approved related artifacts.

## 4. Editorial production contract

Every article, video, newsletter issue, or provider brief must complete the following contract before release.

| Field | Required standard |
|---|---|
| Audience and job | State who is served and what decision or understanding is supported. |
| Scope and exclusion | State what the artifact covers and explicitly does not cover. |
| Source ledger | Link each material factual claim to a source, date, and confidence label. |
| Claim status | Label each central statement as observed, reported, inferred, proposed, or open. |
| Counterargument | State the strongest reasonable alternative explanation or limitation. |
| Disclosure | Name provider, sponsor, referral, ownership, or compensation relationship—or state none known. |
| Review gate | Record author, independent reviewer, approving owner, and approval date. |
| Correction path | Provide a way to request correction, conflict review, or removal. |
| Reusable artifact | Include a checklist, template, decision matrix, glossary, or question library where useful. |
| Prohibited content check | Confirm no false reviews, ratings, investment recommendations, performance claims, confidential data, or generated “facts.” |

## 5. Initial editorial cadence and test

The first test should consist of **four durable pieces**, not 40 shallow pages: (1) a capital-mechanics glossary, (2) a buy-and-build reality check focused on one restoration workflow, (3) a governed-agent/evidence-to-decision architecture note, and (4) a Provider Proof Window pilot brief. Publish only after the P0 questions in the requirements register are answered. Measure qualified readers who reuse an artifact, request a correction, contribute a source, or ask for a scoped proof session. Do not use raw impressions as the primary authority metric.
