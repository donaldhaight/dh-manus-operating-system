# Skill Modernization Brief

**Purpose.** This brief selects the core skills to use before studying the next reference platform, documents the external methods used to improve them, and records the completed revisions. It is deliberately an **independent-platform** workflow: we will learn from publicly observable product behavior and market evidence, then design and build original work rather than copying protected expression or accessing restricted systems.

## Operational Preface for the Next Platform Assessment

When you provide the reference URL, the next phase will begin with a compact intake: intended customer outcome, approved access level, target differentiation, constraints, and the decision you want the clone to support. It will then create a provenance-aware discovery record, convert observations into opportunities and independent requirements, review material product and technical risks, and build only after the resulting specification is ready.

> The working rule is: **observe behavior, validate the customer problem, and implement an original solution.** We will not bypass controls, collect private data, reuse source code or assets, or force every observed feature into the new product.

## External Benchmarking and What Changed

The revisions draw selectively from current specification-driven development, product discovery, accessibility, threat modeling, and skill-authoring practices. GitHub’s Spec Kit formalizes a sequence of constitution, specification, plan, task, implementation, and convergence activities; it supports retaining a governing constitution while adding a concrete implementation-to-specification reconciliation gate.[1] W3C WCAG 2.2 presents testable success criteria, supporting the move from generic accessibility aspiration to proportionate, measurable acceptance criteria.[2] OWASP frames threat modeling as a repeatable lifecycle practice and identifies data-flow models, trust boundaries, and external entities as key inputs, which is now a conditional requirement for meaningful attack surfaces.[3] Current agent-skill guidance reinforces concise progressive disclosure, context-sensitive instruction freedom, specific triggering descriptions, and testing with real usage; the revised skill-authoring workflow adds scenario checks without hard-coding another vendor’s conventions.[4]

| Modernized skill | Principal improvements | Why the change matters |
|---|---|---|
| `clone-to-platform-pipeline` | Added a rights/scope gate; evidence ledger with confidence and permitted-use status; opportunity mapping; original-design boundary; measurable non-functional requirements; proportionate data-flow and abuse-case review; convergence check; and evidence-led delta audits. | The workflow now distinguishes observations from inferences, turns feature study into customer-outcome strategy, and makes traceability, safety, quality, and independent implementation explicit. |
| `dh-method-competitive-intelligence` | Replaced feature-first comparison with outcome-first analysis; added evidence status, source discipline, adoption decisions, assumption tests, calibrated risk review, and traceable delta specifications. | The method now supports real strategic learning and avoids the prior artificial requirement to manufacture critical/high findings. |
| `skill-creator` | Added an update-safe workflow, reusable-content decision table, trigger-quality rules, risk-proportionate guardrails, static validation, and standard/boundary/exclusion scenario testing. | Skills can evolve from actual performance evidence while remaining compact, discoverable, and operationally reliable. |
